This milestone has no user-visible UI (that starts at M0.3). The workspace is
a skeleton: 13 empty library crates and 2 binaries that do nothing yet. What
"manual test" means here is really "does the Nix toolchain work on a clean
clone" — there is no app behavior to click through.

You do not need any PDK or external EDA tool (xschem/ngspice/netgen) for this
milestone's checks.

## Notes for the tester
- `nix flake check` output is verbose; `--keep-going` will run all checks
  even if one fails, which is useful when triaging more than one failure.
- The 13 library crates (`eda-geom`, `eda-db`, `eda-cmd`, `eda-xschem`,
  `eda-pdk`, `eda-netlist`, `eda-sim`, `eda-wave`, `eda-gds`, `eda-verify`,
  `eda-render`, `eda-script`, `eda-ui`) each contain exactly one test,
  `crate_name_is_set`, which just checks `env!("CARGO_PKG_NAME")` against the
  crate's own name from its `Cargo.toml`. This is intentionally trivial —
  these crates have no real functionality yet — but it is a real,
  non-circular check (it reads actual Cargo package metadata) rather than a
  no-op like `assert_eq!(2 + 2, 4)`, and it is what keeps `cargo nextest` (and
  the `workspace-nextest` flake check) from hitting "zero tests collected",
  which `nextest` otherwise treats as a hard error.
