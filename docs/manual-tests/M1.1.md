# Manual test — M1.1 `eda-geom`, `eda-db`, `eda-cmd`: schematic data model and commands

Build: d9b3726   Tester:   Date:   Display server: Wayland / X11

## Nothing to manually check yet

This milestone adds no UI-reachable behaviour. It is a pure data-model and
command-plumbing milestone per `docs/adr/003-schematic-data-model.md`:

- `eda-geom` (`Unit`, `Point`, `Rect`, `Orientation`, `Transform`) and
  `eda-db` (`Id`/`IdAllocator`, `AttributeBag`, `Instance`/`Wire`/`Label`/
  `Pin`, `SchematicView`/`SymbolView`, `Cell`, `Library`, `Design`) are
  library crates with no UI at all.
- `eda-cmd` gains four new commands (`AddInstanceCommand`,
  `MoveInstanceCommand`, `DeleteInstanceCommand`, `AddWireCommand`) and the
  `Patch`/`Edit` plumbing that makes them undoable, but — exactly as
  ADR-003 states — **none of the four is registered in
  `CommandRegistry::with_builtins()`**. The command palette
  (`crates/eda-ui`) only lists builtins; the canvas has no editing tools
  yet (that is M1.5); the keymap files bind no key to any of these four
  command ids. There is currently no way to invoke
  `schematic.add_instance`, `schematic.move_instance`,
  `schematic.delete_instance`, or `schematic.add_wire` from the running
  app at all — not from the palette, not from the canvas, not from the
  keymap.

This is expected, not a gap this session missed: ADR-003 says explicitly
that "palette entries and keymap bindings for editing are M1.5's job, not
M1.1's," and the milestone's own acceptance check
(`docs/MILESTONES.md`, M1.1) is "Unit + property tests; undo then redo
returns identical state" — a statement about the automated test suite, not
about anything visible in the app window. `CommandContext` also grew one
field (`design: eda_db::Design`), but `eda-app`/`eda-ui` still construct
`CommandHost::with_builtins()`, which defaults that field to
`Design::default()` (an empty library, no active cell) — so even the app
shell's behaviour from M0.3 is unchanged: the palette, theme toggle and
`app.hello` status message all work exactly as `docs/manual-tests/M0.3.md`
already describes, and there is nothing new to re-check there either.

## When this checklist will have real content

M1.4 (read-only schematic rendering) will make a `Design` visible on the
canvas for the first time. M1.5 (select/move/rotate/mirror/wire/place/
copy-paste) is the milestone that will register these four commands (or
their M1.5 successors) in the palette and keymap and give a human something
to actually click, drag and undo. Re-visit this file then; until a
milestone wires a UI path to `schematic.add_instance` and friends, there is
no manual test to write for them beyond "did the automated suite pass,"
which the session report already covers.

## Reporting a failure

If a future milestone's manual test for schematic editing fails, the first
diagnostic step is still to ask for a failing automated test in
`crates/eda-db/tests/schematic_model.rs` or
`crates/eda-cmd/tests/schematic_commands.rs` before chasing a UI-level fix —
the data model and command plumbing this milestone built are what every
later schematic-editing feature sits on.
